# Резервные копии

Хранить стоит две вещи, и хранятся они по-разному, потому что различаются по
объёму на три порядка.

## База, которая приходит сама

Каждый день, беззвучно, Studio присылает копию своей базы в тот же чат Telegram,
из которого вы пишете: посты, расписание, состояние доставки, аналитику, внешние
идентификаторы. Настраивать нечего — это включено, пока вы не выключите в
**Настройки → Уведомления → Бэкап базы**.

Это настоящий снимок средствами самой SQLite, а не копия файла. У живой базы
рядом лежит WAL, и обычная копия такой базы — это битая база, которая сообщает о
себе только в момент восстановления.

Чтобы восстановить, скачайте файл из чата и:

```bash
docker compose cp <скачанный>.db app:/data/restore.db
docker compose exec app bun /app/ops/cli.js restore --source /data/restore.db --force
docker compose restart app
```

## Медиа, которые вы устраиваете сами

Медиа в эту копию не входят и войти не могут: файлы намного больше того, что
принимает Telegram. Они лежат в томе `app-data` под `/data` и именно они не
воспроизводимы — это исходные изображения и видео всего, что вы опубликовали.

Solo Publisher намеренно не везёт для них встроенную интеграцию. Ключ к
объектному хранилищу, расписание и политика хранения были бы вторым местом,
которое надо настроить и в котором можно ошибиться, а на любом сервере уже есть
инструмент для этого. Направьте его на том.

**На другую машину** — самое простое, что работает:

```bash
docker run --rm -v solo-publisher_app-data:/data:ro -v ~/.ssh:/root/.ssh:ro \
  instrumentisto/rsync-ssh \
  rsync -a --delete /data/ backup@ваш-второй-сервер:/srv/solo-publisher-media/
```

**В S3 или совместимое хранилище** — через [restic](https://restic.net/), чтобы
копии были инкрементальными и проверяемыми:

```bash
docker run --rm -v solo-publisher_app-data:/data:ro \
  -e RESTIC_REPOSITORY=s3:s3.amazonaws.com/ваш-бакет \
  -e RESTIC_PASSWORD=... -e AWS_ACCESS_KEY_ID=... -e AWS_SECRET_ACCESS_KEY=... \
  restic/restic backup /data
```

Любое из двух ставится в cron на хосте в удобный час. Оба читают том во время
работы Studio; медиафайлы пишутся один раз и не редактируются, так что копия,
снятая посреди записи, в худшем случае даст файл, который подхватит следующий
запуск.

Сначала проверьте имя тома — Compose добавляет к нему имя каталога проекта:

```bash
docker volume ls | grep app-data
```

## Что копировать не нужно

В `caddy-data` лежат TLS-сертификаты, которые Caddy получит заново сам. В
`bot-api-data` — файловый кэш Telegram. Потеря любого из них стоит перезапуска,
а не данных.
